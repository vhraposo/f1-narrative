# V3.17 — Open Questions (resolvidas no design)

> Decisões default adotadas no design para permitir implementação autônoma. Qualquer mudança posterior deve ser registrada em `v3-decisions.md`.

---

**OQ-1 — Cadência de refresh/TTL dos dados externos.**
*Default:* janelas nomeadas em `pilot-knowledge.policy.ts`, sem env novo: perfil estruturado 30 dias, persona 30 dias, relacionamentos 14 dias, eventos 365 dias. Estado calculado em leitura (`FRESH/STALE/UNKNOWN`), nunca afirmado como atual sem verificação. Refresh é sob demanda (admin/por piloto).

**OQ-2 — Granularidade do sync de providers (bulk × por piloto).**
*Default:* por piloto sob demanda; backfill do grid atual via binding existente; pilotos históricos provisionados lazy quando abertos. Sem scheduler/cron nesta fase.

**OQ-3 — Promoção de traits externos para `CharacterPersona`.**
*Default:* **nunca automática**. A camada externa é baseline de leitura; promoção só via `PersonaEvidence` + review ADMIN existente (V3.14). O resolver nunca escreve Persona.

**OQ-4 — Distribuição/versionamento do F1DB.**
*Default:* operador aponta `F1DB_DATA_DIR` para um release extraído; `sourceVersion` = tag do release; sem download em runtime; suíte usa fixtures mínimas.

**OQ-5 — Wikidata ao vivo.**
*Default:* SPARQL opt-in em refresh admin (`WIKIDATA_SPARQL_URL`), com `fetchImpl` injetável; suíte principal nunca acessa a Internet (fixtures gravados).

**OQ-6 — Modelo de override de relacionamento no Universe.**
*Default:* tabela universe-scoped `UniverseDriverRelationship` (novo); `Relationship` (Character↔Character com `dimensions`) permanece intocado; alvo pode ser Character existente ou pessoa pública externa (sem criar Character).

**OQ-7 — Geração de biografia.**
*Default:* composição determinística a partir de fatos estruturados + marcos + interesses + relações verificadas; LLM (se usado) apenas como extrator/reescritor de legibilidade com grounding obrigatório, desligado por padrão e injetável. Sem cópia de frases da fonte.

**OQ-8 — Integração no prompt.**
*Default:* nova seção opcional `PILOT_CONTEXT` (após `CHARACTER_DNA`), speaker-only, cap 2000 chars, sem confidence/source metadata/IDs; `generationKey` continua via `systemPrompt` (mecanismo inalterado); `CURRENT_TURN`/RAG/SSE/NullProvider preservados.

**OQ-9 — Extração de persona com LLM.**
*Default:* interface `PilotPersonaExtractor` com implementação determinística para testes e implementação provider-backed opt-in; saída validada por zod com `SUPPORTED|UNSUPPORTED|UNCERTAIN`; `INFERRED` exige ≥2 evidências; conflito vira `CONFLICT`.

**OQ-10 — Correção V3.15 com narrative stale.**
*Default:* nenhuma regeneração automática na V3.17; o resolver lê o estado atual do Universe (correções visíveis) e segue usando os dados disponíveis; interação documentada no doc de arquitetura.

**OQ-11 — Persona no DEV (Internal Server Error).**
*Default:* DEV permanece protegido (27 migrations, sem deploy). O backend degrada graciosamente (`503 UNAVAILABLE` sanitizado; UI amigável) e os endpoints V3.17 fazem o mesmo. Ambientes migrados funcionam normalmente.

**OQ-12 — Rivalidade.**
*Default:* nunca inferida; só entra com suporte explícito (`OTHER_PUBLIC_RELATION`/texto) ou permanece ausência de dado.

**OQ-13 — Memória × evento histórico.**
*Default:* `ExternalDriverEvent` é baseline histórica; `Memory` continua exclusiva do Universe; nenhuma materialização automática de memória.
