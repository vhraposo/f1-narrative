# V3.18 — Pilot Experience, Memory & Evolution: Arquitetura

> **Status:** implementado (V3.18 concluída). Base: HEAD `3c88d37` (V3.17 concluída; V3.14/V3.15/V3.16/V3.17 verdes).
> **Princípio:** LLM nunca é autoridade do estado do personagem. Experience/Memory/Evolution são determinísticas, explícitas, Universe-scoped e auditáveis.

---

## 1. Objetivo

Transformar acontecimentos do Universe em contexto experiencial persistente:

```
Timeline / World Event → Experience → Memory → Context Resolver → Conversation
Relevant Experience → Evolution Rule → Persona Change → CharacterPersona (append-only, baseline+deltas)
```

Sem LLM decidindo o que aconteceu, sem psicologia automática, sem segundo sistema temporal, sem contaminação entre Universes e sem tocar External Knowledge.

---

## 3. Modelo de dados (migration `add_pilot_experience_memory_evolution`)

### 3.1 Enums

- `PilotExperienceType`: `CAREER_MILESTONE | SPORTING_VICTORY | SPORTING_DEFEAT | CHAMPIONSHIP | TEAM_CHANGE | RELATIONSHIP_EVENT | CONFLICT | PERSONAL_MILESTONE | NARRATIVE_EVENT | SIGNIFICANT_RACE | OTHER_RELEVANT_EXPERIENCE` (pequeno e explícito; usado por Experience e Memory).
- `PilotExperienceSource`: `RACE_RESULT | STANDING | TIMELINE_CORRECTION | UNIVERSE_EVENT | RELATIONSHIP | CURATED`.
- `PilotExperienceStatus`: `ACTIVE | INVALIDATED | SUPERSEDED`.
- `PilotMemoryDerivation`: `MANUAL | DERIVED | RULE_DERIVED`.
- `PilotMemoryStatus`: `ACTIVE | ARCHIVED | SUPERSEDED | INVALIDATED`.

### 3.2 `PilotExperience` (nova)

`id`, `universeId` (FK Cascade), `characterId` (FK Cascade), `experienceType`, `source`, `sourceKey` (chave natural determinística), `seasonYear Int?`, `seasonId?` (FK SetNull), `raceId?` (FK SetNull), `eventId?` (Event, SetNull), `timelineEventId?` (TimelineEvent, SetNull), `occurredAt DateTime?`, `salience MemoryImportance @default(MEDIUM)`, `title`, `summary?`, `status PilotExperienceStatus @default(ACTIVE)`, `invalidationReason?`, `revision Int @default(1)`, `createdAt/updatedAt`. Unique `[universeId, characterId, source, sourceKey]`; índices `[universeId, characterId, status]`, `[universeId, seasonId]`, `[universeId, raceId]`.

Experience é projeção determinística: mesmo estado ⇒ mesmas linhas (upsert idempotente). Sem texto livre como única representação (tipo + chaves + resumo).

### 3.3 `Memory` (estendida, sem quebrar o existente)

Novas colunas: `universeId String? @db.Uuid` (FK Universe Cascade), `memoryType PilotExperienceType?`, `derivation PilotMemoryDerivation @default(MANUAL)`, `status PilotMemoryStatus @default(ACTIVE)`, `revision Int @default(1)`, `experienceId?` (FK PilotExperience SetNull), `timelineEventId?` (FK TimelineEvent SetNull), `derivedKey String?`, `updatedByRevisionAt DateTime?`. Índices `[universeId, status]`, `[universeId, derivedKey]` (não-unique: histórico via status), `[experienceId]`.
`importance` continua sendo a **saliência** (LOW/MEDIUM/HIGH/CRITICAL). `emotionalImpact` permanece intocado e NÃO é calculado automaticamente (evita psicologia inferida).

### 3.4 `PersonaTraitEvolution` (nova, append-only)

`id`, `personaId` (FK Cascade), `traitKey`, `ruleCode`, `sourceExperienceId?` (SetNull), `value String?` (texto canônico apenas para criação por regra; nunca derivado de LLM), `confidenceDelta Float`, `reason String`, `fingerprint String @unique` (sha256 de universe+character+rule+experience), `appliedAt @default(now())`. Índices `[personaId, traitKey]`.

`CharacterPersona` ganha `evolutionRevision Int @default(0)` e `evolutionAppliedAt DateTime?`.

`TimelineEventKind` ganha `PERSONA_UPDATED` (auditoria append-only, state-neutral no replay), com payload `{characterId, ruleCode, traitKey, beforeConfidence, afterConfidence, experienceId, fingerprint}`.

## 4. Domain rules

### 4.1 Experience derivation (determinística, sem LLM)

| Fonte | Experiências derivadas |
|---|---|
| RaceResult (Universe, corrida FINISHED) | `SPORTING_VICTORY` (P1), `SPORTING_DEFEAT` (participação sem pódio quando o piloto tinha expectativa alta? **não** — v1: apenas P1 vitória, primeiro pódio/primeiro ponto como `CAREER_MILESTONE`, DNF como `SIGNIFICANT_RACE`) |
| ChampionshipStanding (temporada finalizada/P1 no corrente) | `CHAMPIONSHIP` (P1); perda de título detectada por mudança de P1 entre revisões → experience de `SPORTING_DEFEAT` na invalidação/reconciliação |
| SeasonDriverEntry/Team (mudança de equipe entre temporadas) | `TEAM_CHANGE` |
| Event marcado significativo (importância HIGH/CRITICAL) com participantes | `NARRATIVE_EVENT` (somente `source=UNIVERSE_EVENT`, nunca News em massa) |
| `UniverseDriverRelationship` cria/atualiza/encerra | `RELATIONSHIP_EVENT` |
| Timeline correction aplicada | invalidação das Experiences afetadas (ver §4.4) — novas Experiences surgem na reconciliação |
| Evento curável explícito (API `reconcile` com `curatedExperiences`) | `PERSONAL_MILESTONE`/`OTHER_RELEVANT_EXPERIENCE` (source `CURATED`) |

Nenhuma experience para futuro (`occurredAt > worldState.currentDate` quando datas existirem) e nenhuma experience para RaceResult de corrida não finalizada.

### 4.2 Memory projection (Experience → Memory)

Gatilhos explícitos (senão a Experience existe sem Memory):

- `CHAMPIONSHIP` (título) → Memory `CHAMPIONSHIP`, salience HIGH.
- `SPORTING_VICTORY` **primeira da carreira no Universe** (por temporada/contagem) → `SPORTING_VICTORY` HIGH; vitórias seguintes → `SIGNIFICANT_RACE` LOW/MEDIUM (configurável por regra).
- `TEAM_CHANGE` → `TEAM_CHANGE` MEDIUM.
- `RELATIONSHIP_EVENT` com mudança de estado (start/end) → `RELATIONSHIP_EVENT` MEDIUM.
- `NARRATIVE_EVENT` importância CRITICAL → `NARRATIVE_EVENT` HIGH; HIGH → MEDIUM.
- `SPORTING_DEFEAT` de título → `SPORTING_DEFEAT` HIGH.
- `CONFLICT` (experiência explicitamente curada/derivada de relação CONFLICTED) → `CONFLICT` HIGH.
- `CAREER_MILESTONE` (first point/podium/pole) → `CAREER_MILESTONE` MEDIUM.

Regras em `pilot-experience.memory-rules.ts` (puras, testáveis). Texto renderizado a partir do structured (`renderMemory(type, context)`) — nunca a única representação; nunca copia conteúdo de fonte externa; nunca afirma emoção.

### 4.3 Salience, validity e ordering

- Salience = `importance` (LOW/MEDIUM/HIGH/CRITICAL) — "utilidade para contexto futuro", não psicologia.
- Status: `ACTIVE` (usável), `ARCHIVED` (usuário arquivou manual), `SUPERSEDED` (substituída por versão mais nova da mesma derivedKey), `INVALIDATED` (fato-base deixou de existir).
- Seleção no resolver: ACTIVE apenas; ranking determinístico: relevância direta ao tópico (ano/corrida/piloto/time/tipo) → salience → recência (distância do worldDate) → recorrência (tipo repetido) → career-defining (CHAMPIONSHIP/CAREER_MILESTONE) → id. Nunca `ORDER BY createdAt` puro.
- Histórico append-only: nunca DELETE de Memory derivada; correção invalida e a reconciliação cria replacement com `revision+1`.

### 4.4 Correção (V3.15/V3.16) → invalidação determinística

Executada **na mesma transação** de `applyCorrection` (após o replay, sob o lock existente), sem LLM e sem recompute pesado:

- `RACE_RESULT_CORRECTED` / `RACE_SESSION_RESULT_CORRECTED` → invalida Experiences ACTIVE do universe com `raceId = command.raceId` **ou** `seasonId = season da corrida` (standings mudam junto); Memories derivadas dessas experiences → `INVALIDATED`.
- `STANDING_CORRECTED` → invalida por `seasonId`.
- `NUMBER_CORRECTED` / `RACE_UPDATED` → sem efeito experiencial (documentado).
- Nada é deletado; replacement surge na próxima `reconcile`.
- `narrative stale` continua sem regeneração automática (D-065 preservado).

### 4.5 Reconcile (write path explícito)

`reconcilePilotExperiences(universeId, characterId, { now })`:

1. carrega fatos-fonte (results, standings, entries, events, relationships, curated existentes);
2. deriva experiences (pure) e faz upsert por `[universeId, characterId, source, sourceKey]` (idempotente);
3. invalida ACTIVE sem backing (ex.: result corrigido sumiu do conjunto derivado) com `invalidationReason`;
4. projeta memories por regra; para cada `derivedKey` mantém 1 ACTIVE (create/replace com `revision+1`; anteriores → `SUPERSEDED` se substituídos por valor novo, `INVALIDATED` se a experience sumiu);
5. **preserva MANUAL integralmente** (nunca sobrescreve/remove);
6. retorna relatório determinístico `{experiencesCreated/Updated/Invalidated, memoriesCreated/Superseded/Invalidated, skipped}`.

Idempotência: rodar 2× sem mudanças ⇒ segundo run é no-op (mesmas chaves). Nunca roda em chat/page load; somente `POST .../reconcile` explícito.

### 4.6 Persona evolution (baseline + deltas append-only)

- **Baseline:** traits MANUAL/EVIDENCE continuam a base (V3.14). Efeitos derivados **nunca** reescrevem `PersonaTrait.value/confidence`.
- **Efeito:** `PersonaTraitEvolution` registra `confidenceDelta` (e `value` apenas quando a regra cria trait inexistente com texto canônico fixo, ex.: `confidence: "Elevada"`).
- **Effective confidence** (calculada na leitura): `clamp(base + Σ deltas ATIVOS, 0, 1)`; MANUAL vence em valor e a regra é registrada como `skipped-manual` (auditável), não aplicada ao display.
- **Regras v1** (poucas, explícitas, documentadas em `v3.18-evolution-rules.md`):
  - `FIRST_WORLD_CHAMPIONSHIP` → `confidence` +0.06 (HIGH salience CHAMPIONSHIP experience; aplica 1× por experiência).
  - `CHAMPIONSHIP_REPEAT` → `professionalPriorities` +0.03 (título adicional).
  - `MAJOR_DEFEAT` → `emotionalExpression` +0.03 (experiência SPORTING_DEFEAT HIGH/CRITICAL curada/derivada de perda de título) — expressão pública mais contida; **sem** juízo psicológico.
  - `TEAM_CHANGE_STABILITY` → `behavioralTendencies` +0.02 (TEAM_CHANGE).
  - Valores/deltas são constantes nomeadas e testadas; nenhum trait de saúde/estado mental.
- **Idempotência/double-count:** `fingerprint = sha256(universeId+characterId+ruleCode+experienceId)` com `@unique`; segunda aplicação ⇒ `ALREADY_APPLIED`/no-op (mesmo padrão do `ATTRIBUTE_EVOLVED`).
- **Cumulatividade proibida:** nunca mutar o valor corrente em loop — o efetivo é sempre `base + Σ efeitos` (baseline estável).
- **Conflito:** somar deltas por traitKey é determinístico; desempate/ordem de avaliação por `rulePriority` nomeada + `ruleCode` + `experience.id` (nunca por ordem de execução/tempo).
- **Preview/Apply:** `POST /api/pilot-context/:characterId/evolution/preview` retorna `{traits:[{key, label, beforeConfidence, afterConfidence, baseConfidence, reasons:[{ruleCode, experienceId, delta, summary}]}], revisionBefore/After, skipped}`; `POST .../evolution/apply` revalida que o preview corresponde ao estado atual (fingerprint do conjunto de efeitos pendentes) e aplica em transação sob `lockUniverseTimeline`, incrementa `evolutionRevision`, grava `PERSONA_UPDATED` (audit). Sem apply cego: apply exige `expectedRevision` retornado pelo preview (409 `EVOLUTION_STALE` se mudou).

### 4.7 Relationship experience

- Mudanças de `UniverseDriverRelationship` (create/update state ENDED) geram `RELATIONSHIP_EVENT` na reconciliação (derivada de linhas, não de hooks frágeis).
- `TEAMMATE` com estado ACTIVE→ENDED gera `RELATIONSHIP_EVENT` + Memory MEDIUM ("relação de equipe encerrada"); nunca "sentiu-se traído" (sem emoção automática).
- Dimensões de `Relationship` NÃO são mutadas automaticamente nesta fase (event-evolution existente continua sendo o único escritor de dimensions).

### 4.8 Temporalidade / POV histórico

- `occurredAt`/`seasonYear` permitem filtrar memórias por janela temporal simples quando o contexto da conversa indicar ano/período (`topic` com ano delimitado); nada de segundo motor temporal.
- Experiences/Memories futuras ao `worldState.currentDate` não são criadas.

## 5. Integração com contexto e geração

- `PilotContextResolver` passa a ler `Memory` com `status=ACTIVE` + `universeId` do universe do speaker, ranqueando por §4.3 (mantendo cap 6) e incluindo `memoryType`/`salience`/`experienceId` no view (não no prompt).
- Fingerprint do resolver passa a incluir `{memoryId, revision, memoryType}` + `evolutionRevision` + status; `generationKey` continua derivado do `systemPrompt` (mecanismo inalterado) — mudanças relevantes de memória/persona evoluída invalidam automaticamente.
- `context.assembly` (seção `MEMORIES` global) filtra `status=ACTIVE` para não expor memória invalidada (regressão mínima).
- Prompt: memórias continuam textuais e bounded; sem confidence/IDs/status/provenance crua; sem "eu lembro" forçado (invariantes existentes preservadas).
- Preservados: speaker-only, `CURRENT_TURN`, RAG, research, SSE, NullProvider, projection, AI Behavior (inalterado — documentado).

## 6. API e UI

Endpoints (owner-only, leak-safe 404; naming segue módulos existentes):

- `GET /api/pilot-context/:characterId/memories?status=&type=&importance=` — lista com tipo/salience/origem/estado/fonte.
- `POST /api/pilot-context/:characterId/memories` — Memory MANUAL (título/content/tipo/importância/data; nunca cria claim externo).
- `PATCH /api/pilot-context/:characterId/memories/:id` — apenas MANUAL (derived → 409 `DERIVED_MEMORY_IMMUTABLE`); permite arquivar (`status=ARCHIVED`).
- `POST /api/pilot-context/:characterId/reconcile` — executa reconciliação determinística (owner).
- `POST /api/pilot-context/:characterId/evolution/preview` / `apply` — evolução determinística (owner) com `expectedRevision`.
- `GET /api/pilot-context/:characterId/experiences` — inspeção (owner).

UI: nova aba **Memórias** (lista/filtros/tipo/importância/origem/estado/source) + card **Evolução da persona** na aba Persona (preview before/after, razão, experiência-fonte, apply explícito, "afeta somente este Universe"). Sem JSON cru, sem internals.

## 7. Segurança, privacidade e performance

- Tudo Universe-scoped e owner-only; ADMIN não ganha acesso global novo.
- Nunca DELETE destrutivo de história; estados marcam.
- Sem inferência psicológica/saúde; EmotionalImpact não é calculado.
- Sem background jobs/cron: reconcile/evolution são explícitos.
- Reconcile não roda em chat/page load; resolver é read-only e usa query indexada.
- Cleanup de testes: apósAll para experiences/evoluções/memories + extensão dos helpers existentes (zero órfãos; cascade onde já existe).
