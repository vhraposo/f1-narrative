## Findings

### CRITICAL

**C-1 — `POST /api/timeline/corrections` (legado) permite escrita fora do Universe e corrupção global.**
Evidência: `timeline.routes.ts:43-54,383-410` (payload `z.record` livre, sem schema tipado, sem filtro de `points`); `timeline.service.ts:589-649,651-721` (`id: undefined` faz Prisma ignorar filtro → guardas passam); replay `timeline.service.ts:272-294,362-380` (`updateMany` sem filtro de universe quando ids ausentes). Um payload `{"kind":"RACE_RESULT_CORRECTED","payload":{"position":1}}` altera **todos** os RaceResult do banco; `NUMBER_CORRECTED` idem para entradas de temporada. Evento envenenado quebra `recompute`/`advance`.
Impacto: integridade/dados cross-tenant; DoS por replay. Risco: altíssimo.
Correção proposta: selar a rota (409 `USE_TIMELINE_CORRECTION`) — o caminho tipado (preview/apply) já valida universe/token. Teste: rota → 409; dados intactos.

### HIGH

**H-1 — Event PATCH/DELETE sem ownership.** `prisma/schema.prisma` Event global sem owner; `event.routes.ts:165-234,236-281` só verifica existência; DELETE cascadeia Memory/NewsItem de outros tenants. Correção: exigir dono de ≥1 participante ou ADMIN; 404 leak-safe. Testes: cross-user 404; owner ok; cascade bloqueado.

**H-2 — Memory aceita qualquer Character e vaza `userId`.** `memory.routes.ts:86-93` (`characterExists` sem ownership) usado em `195-217` e `483`; resposta inclui `userId` (`17-24`). Impacto: injeção de memória no feed de outro usuário + oracle de existência. Correção: `characterAccessible(userId, id)` (próprio, AI do próprio universe, catálogo global) e remover `userId` da resposta. Testes: participante de terceiro → 404; resposta sem `userId`.

**H-3 — View de relacionamentos devolve linha Prisma crua.** `pilot-knowledge.relationships.ts:243-249,346,392-406,429-439` expõe `universeId`/`createdById`. Correção: view model `{id, kind, displayName, state, validFrom, validTo, updatedAt}` na view e nas respostas; web ajustado. Testes de contrato.

**E-1 — Efeitos de evolução não são revogados quando a experiência-fonte é invalidada (FASE 9).** `persona-evolution.service.ts` soma todos os efeitos persistidos; `PersonaTraitEvolution` sem status. Cenário: E1 (+0.10) → 0.70; invalidar E1 deve voltar a 0.65 — hoje continua 0.70. Correção: coluna `status` (ACTIVE/SUPERSEDED) + filtro por status da source em resolver/preview/apply + persistência da suprecessão no apply; fingerprint do preview inclui revogados. Testes: sequência 0.60→0.70→no-op→0.75→invalida E1→0.65; MANUAL vence.

### MEDIUM

**F-2 — `reconcilePilotExperiences` sem transação/lock.** `pilot-experience.reconcile.ts` faz múltiplas escritas sem lock; duas reconciliações concorrentes podem criar duas memórias ACTIVE com o mesmo `derivedKey` (derivedKey não é unique). Correção: rodar dentro de `$transaction` com `lockUniverseTimeline`; teste de concorrência (reconcile×reconcile e reconcile×correction) sem duplicatas/híbridos.

**F-3 — Invalidação por correção não incrementa `revision`.** `pilot-experience.reconcile.ts` `updateMany` sem incremento. Correção: `revision: { increment: 1 }`; teste.

**F-4 — Erros de domínio viram 500 em pontos específicos.** pilot-knowledge relationships update/delete; memory PATCH; event participants DELETE; event PATCH (P2002 do event-evolution). Correção: mapear P2025→404/P2002→409.

**F-5 — Contratos de erro inconsistentes/enganosos.**
- código real da imutabilidade de memória derivada é `VALIDATION_ERROR` (docs prometem `DERIVED_MEMORY_IMMUTABLE`) → padronizar código novo.
- refresh exausto devolve 502 com código `DRIVER_NOT_FOUND` → `REFRESH_FAILED`.
- alvo de `targetCharacterId` de outro universe devolve 400 → 404 leak-safe.
- events/news devolvem 403 para referência de outro universe (oracle de existência) → 404.
Correção: padronizar + testes atualizados.

**F-6 — `TIMELINE_KINDS` omite `PERSONA_UPDATED`.** `timeline.read.ts:5-15` — filtro de kind não seleciona o novo kind e a UI cai no fallback. Correção: adicionar kind + label web; teste de filtro.

**F-7 — `POST /api/timeline/recompute` sem try/catch/limite.** Após C-1 selado o vetor cai, mas recompute segue sem tratamento consistente. Correção: manter owner-scoped e mapear errors (sem novo gate).
