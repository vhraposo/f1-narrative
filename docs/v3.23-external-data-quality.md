## 3. F1DB (dataset real, offline)

- **Snapshot vendorizado** em `data/external/f1db/` (subset do release `v2026.15.1`): circuits, layouts, grands-prix, drivers, seasons, seasons-driver-standings, races, race-results + `LICENSE`, `checksums_sha256.txt` e `PROVENANCE.json` (asset sha256, retrievedAt, generatorVersion).
- **Provider** `apps/api/src/modules/f1db/`: parser CSV próprio (`f1db.csv.ts`), dataset lazy cacheado (`F1DB_DATA_DIR` ou caminho do repo), resolver de circuito com alias Ergast→F1DB (`red_bull_ring`→`spielberg` etc.) e fallback por nome, e resolver de piloto (nome curto/complete/abbreviation/surname+initial).
- **Circuitos**: catálogo e detalhe usam F1DB como autoridade técnica (extensão em metros, curvas, tipo, direção, `placeName`, primeiro/último GP e nº de corridas) com `provenance.source = F1DB` e `sourceVersion`; fallback para o espelho quando não resolvido.
- **Layouts**: `data/external/f1-circuits-svg/` (minimal black/white-outline, commit c1bcd6f, CC BY 4.0, ROY Jules). Endpoint `GET /api/external/circuits/:id/layout.svg?style=` serve o SVG do layout vigente (fallback para layouts anteriores), sanitizado em runtime (sem `<script>`, `<foreignObject>`, `on*`, `javascript:`, limite 200KB), com `Cache-Control` e headers de atribuição ASCII-safe.
- **Validação cruzada**: teste dedicado confirma que os campeões 2000–2025 do dataset batem com a lista canônica (nomes com sobrenome materno aceitos via matching normalizado).

## 4. Marcos históricos reais

- `pilot-knowledge.events.ts` agora mescla, quando um piloto resolve no F1DB, a **primeira ocorrência no histórico completo** para `F1_DEBUT`, `FIRST_POINT`, `FIRST_PODIUM`, `FIRST_POLE`, `FIRST_WIN`, `FIRST_FASTEST_LAP` e títulos (CHAMPIONSHIP/FIRST_CHAMPIONSHIP).
- Regra determinística: F1DB vence apenas quando o ano é **estritamente anterior** ao marco do espelho; prune de marcos obsoletos mantido; eventos F1DB carregam `sourceId` do ledger (`F1DB`, `STRUCTURED_RELEASE`, CC BY 4.0) — provenance real, sem LLM.
- Teste de aceitação: piloto “Lando Norris” com espelho parcial 2026 → marcos derivados 2019 (estreia), 2020 (pódio), 2021 (pole), 2024 (vitória), 2025 (título), com fonte F1DB.

## 5. Perfil factual e biografia

- **Overview/perfil**: `dateOfBirth` e `placeOfBirth` caem para o F1DB quando o `sourceRecord` (Jolpica) não tem (Lando → `1999-11-13`, `Bristol`); `driverCode` cai para a abbreviation F1DB; títulos/debut unem espelho + F1DB; `nationality` continua localizada em pt-BR pelo resolver global.
- **Biografia determinística** ganhou a sentença de carreira (“Na carreira na Fórmula 1, soma X vitórias, Y pódios… e N títulos”).
- **Composer de biografia** (`biography.composer.ts`):
  - prompt canônico (apenas evidence bundle, sem diagnóstico/invenção/cópia, 5–8 parágrafos, português);
  - claims derivados dos fatos estruturados (nascimento, local, nacionalidade pt-BR, estreia, equipes, títulos, estatísticas, marcos);
  - LLM **opcional** via `GenerationProvider` existente (Ollama quando configurado; `nullProvider` → fallback determinístico);
  - saída sanitizada (sem HTML/URLs/markdown, cap 2400, mínimo 80 chars);
  - persistência com `ExternalKnowledgeSource` (`CURATED`/`BIOGRAPHY_PAGE`, metadata `generator/generatorVersion/claimsCount`); bio gerada é **preservada** na reabertura (não regenera LLM); falha do composer nunca quebra o provisionamento.

## 9. Limitações e adiados

1. **Foto de circuito licenciada**: nenhum provider de mídia configurado; resolver devolve indisponível (sem inventar).
2. **Recorde oficial de volta**: o subset F1DB não inclui lap records; permanece `available:false` com razão (volta mais rápida em corrida disponível via Jolpica).
3. **OpenF1**: integração existente (headshots) não foi estendida nesta fase; usar apenas 2023+ quando fizer sentido.
4. **Persona estruturada ampliada** (FASE 14 do pedido): o registry de traits públicos existente foi mantido; novos campos como `mentalidadepública` não foram adicionados para não criar psicologia inventada sem evidência.
5. **Biografias ricas de prosa oficial**: o composer produz texto original a partir de claims; enriquecimento com fontes primárias (Formula1.com) exigiria fetch allowlisted + extração — adiado (sem crawler).
6. **Backfill histórico no espelho** (importar F1DB para ExternalRace/Result em massa): adiado; o provider cobre marcos/perfil/circuitos offline sem ETL.
