# V4.7 — Autonomous Universe

## Objetivo

Permitir que o Universe continue funcionando sem intervenção manual, com kill switch, dry-run,
budgets, fairness, retry-safe e isolamento — conectando V4.5 (tick) e V4.6 (race consequences) ao
Behavior/Command Layer (V4.1–V4.2).

## Auditoria

- Não existe fila durável no projeto; o runner é explícito (rota) e o tick já é idempotente por
  fingerprint (V4.5). Decisão: **não** adicionar pg-boss/Redis nesta fase — PostgreSQL + unique
  fingerprint + advisory locks existentes atendem o volume; a fila durável fica como evolução
  documentada.
- Behavior V4.1 executa comandos com lock, stale e idempotência; `AUTONOMOUS_TICK` agora gera
  candidatos SEND_MESSAGE/CREATE_MEMORY/UPDATE_RELATIONSHIP/CREATE_EVENT (antes só CREATE_EVENT).

## Estado de autonomia

`Universe`: `autonomyMode` (OFF/OBSERVER/GUIDED/FULL), `autonomyStatus` (ACTIVE/PAUSED/STOPPED),
`lastSimulationAt`, `nextSimulationAt`, `simulationVersion`. WorldState permanece a autoridade
temporal — o cursor de simulação é separado.

## Pipeline (`autonomy.service.ts`)

`runAutonomousTick({ universeId, dryRun?, toDate? })`:

1. Kill switch: mode OFF → `AUTONOMY_DISABLED`; status PAUSED/STOPPED → `AUTONOMY_PAUSED/STOPPED`
   (zero ações).
2. Janela: `from = lastSimulationAt ?? WorldState.currentDate`; `to = toDate ?? from + 24h`;
   `to <= from` → `WINDOW_ALREADY_PROCESSED` (reuso, sem reprocessar).
3. `runSimulationTick` (V4.5) — schedules → eventos/news; races FINISHED da janela →
   `processRaceConsequences` (V4.6). Tick repetido → `REUSED` (sem behavior pass).
4. Behavior pass: AI characters ordenados por fairness determinística (última decisão mais antiga
   primeiro, `id` como desempate), limitados por `AUTONOMY_MAX_CHARACTERS_PER_TICK`.
   Alvo = primeira relationship (ordem id); conversa DM/GROUP existente entre o par é usada quando
   houver; decisão `AUTONOMOUS_TICK` persistida (audit) com `tickId` (guard anti-duplicata).
5. Execução apenas em FULL: `executeBehaviorDecision` (Command Layer, lock/stale/idempotência);
   budgets por tipo (mensagens, eventos, memórias, relações) + `maxActionsPerTick`; OBSERVER avalia
   sem executar; GUIDED mantém decisões para aprovação (sem execução).
6. Cursor: `lastSimulationAt = to`, `nextSimulationAt = to + 24h`, `simulationVersion = autonomy.v1`.

Dry-run: tick em modo DRY_RUN + plano de behavior via `resolveCharacterGoals`/`evaluateBehaviorPolicy`
puros (sem AiDecision, sem mutações).

## Budgets (env)

`AUTONOMY_MAX_ACTIONS_PER_TICK` (3), `AUTONOMY_MAX_MESSAGES_PER_TICK` (2),
`AUTONOMY_MAX_EVENTS_PER_TICK` (2), `AUTONOMY_MAX_MEMORY_WRITES_PER_TICK` (2),
`AUTONOMY_MAX_RELATIONSHIP_CHANGES_PER_TICK` (2), `AUTONOMY_MAX_CHARACTERS_PER_TICK` (5),
`AUTONOMY_MAX_LLM_CALLS_PER_TICK` (0 — sem LLM no loop), `AUTONOMY_TICK_WINDOW_HOURS` (24).

## Endpoints

- `GET /api/universe/autonomy` (owner) — estado.
- `PATCH /api/universe/autonomy` — `{ mode?, status? }` (kill switch).
- `POST /api/universe/autonomy/tick` — `{ dryRun?, toDate? }` (um tick por chamada; sem loop HTTP).

## Invariantes

- USER characters nunca entram no behavior pass (filtro `controlledBy = AI`).
- Cross-universe: characters/relações/races escopados ao Universe; comandos revalidam alvo.
- Retry/duplicata: fingerprint do tick + guard `tickId` nas decisões + idempotência dos comandos.
- LLM: zero chamadas (`maxLlmCalls = 0`); falha de provider não existe neste caminho.
- Cânone intocado (RaceResult/Standing/WorldState).

## Testes

`autonomy.test.ts` (9): OFF, PAUSED, OBSERVER sem execução, FULL executa e avança cursor, USER
isolado, dry-run sem writes, budget, tick repetido reutilizado, rotas owner.

## Limitações

- Sem worker agendado/daemon (invocação explícita); pg-boss documentado como evolução se necessário.
- GUIDED não possui fluxo de aprovação (apenas avalia).
- Fairness por última decisão; sem prioridade por goal (evolução futura).
