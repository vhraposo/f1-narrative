# V3.14 — Driver Persona / AI Character Profiles: Relatório Final

> Branch `V3-NewFeats` · 2026-09-30 · commits V3.14.1–V3.14.9 (locais, sem push/merge).

## 1. Objetivo

Adicionar uma camada de **Persona** — como cada personagem/piloto tende a falar, reagir e se comportar — separada de identidade, memória, relações, atributos esportivos e fatos externos, com curadoria por evidências e integração ao prompt de geração.

## 2. Arquitetura

`External Mirror → Universe → Character/DriverProfile → Persona (PersonaTrait/PersonaEvidence) → Generation Context (slot CHARACTER_DNA) → systemPrompt → provider`

- Persona é 1:1 com Character (D-050), sem `universeId` redundante.
- Rules puras são a única fonte de verdade (D-059); service é o único writer; API/UI apenas consomem.
- `Character.dna` permanece intacto e é fallback legado (OQ-6).
- Evidence nunca entra no prompt; nenhum sistema temporal novo (D-058).

## 3. Models

- `CharacterPersona` (origin, summary, schemaVersion, createdById) — `characterId @unique`.
- `PersonaTrait` (key, value, confidence, sourceKind, evidenceId SetNull) — `@@unique([personaId, key])`.
- `PersonaEvidence` (traitKey, proposedValue, sourceType, title, url, publishedAt, excerpt, confidence, status, created/reviewedBy/At).
- Enums: `PersonaOrigin`, `PersonaTraitSource`, `PersonaEvidenceType`, `PersonaEvidenceStatus`.

## 4. Rules (`persona.rules.ts`)

Registry único (8 keys, labels, prioridades 1–8, cap 200); constantes de caps (12/2000/600/200/500/2048); validação pura (key, value, summary, confidence, proposedValue, título, excerpt, URL, publishedAt, sourceType); sorting determinístico (priority → confidence desc → key asc); autoridade de evidence (confidence → publishedAt nulls last → createdAt → id); confidence (MANUAL 1.0; EVIDENCE = autoridade; ausência = NONE); transições de status; precedência MANUAL > EVIDENCE; classificação de conflito; `planPersonaTraitReconcile`.

## 5. Service (`persona.service.ts`)

`resolvePersonaAccess` (OWNER_CHARACTER / OWNER_UNIVERSE / GLOBAL_AI_CATALOG / FORBIDDEN / NOT_FOUND, leak-safe), `resolvePersonaOrigin`, `getPersonaView` (nunca escreve), `ensurePersona` (lazy, P2002-safe), `updatePersonaManually`, `deletePersonaTrait`, `createPersonaEvidence`, `reviewPersonaEvidence` (ADMIN + `pg_advisory_xact_lock('persona:<id>')` + reconcile na mesma transação). Erros `PersonaServiceError` (NOT_FOUND, TRAIT_NOT_FOUND, EVIDENCE_NOT_FOUND, FORBIDDEN, VALIDATION_ERROR, INVALID_TRANSITION).

## 6. Mutações manuais

PATCH é upsert somente de linhas MANUAL (traits omitidos intactos; `summary: null` limpa; nenhum campo de servidor aceito; keys duplicadas = 400); trait EVIDENCE é convertido para MANUAL (confidence 1.0, evidenceId null) sem tocar na evidência; DELETE explícito não ressuscita trait; operações atômicas; `{summary:null}` sem Persona = NO_CHANGE.

## 7. Workflow de Evidence

Create exclusivo do dono (Persona lazy, status PROPOSED, createdById); review ADMIN-only com transições válidas (mesmo status = 409), auditoria `reviewedBy/At`, override opcional de confidence; reconcile determinístico (cria/atualiza/remove trait EVIDENCE; MANUAL sempre vence) com lock por Persona; conflitos coexistem sem erro; evidence preservada integralmente.

## 8. API

`GET/PATCH /api/characters/:characterId/persona`, `DELETE .../persona/traits/:traitKey`, `POST .../persona/evidence` (201), `PATCH /api/persona-evidence/:evidenceId`; Zod `.strict()`; resposta `{ persona }`; erros mapeados 400/403/404/409 sem stack/SQL/Prisma.

## 9. Integração de geração

`composePersonaPromptBlock` renderiza summary (cap 600) + traits (cap 12/200/2000) no slot `CHARACTER_DNA` com preâmbulo de tendência (D-060); precedência Persona → dna → biography → omissão; apenas a persona do speaker é carregada (1 query, 0 evidence); `generationKey` muda quando a persona do speaker muda e não muda por persona de terceiros; SSE/projeção/NullProvider inalterados; reasons de truncamento em `omitted`.

## 10. UI

`PersonaSection` em Character (resumo/traits) e Driver (com evidências); editor de summary, traits com labels do registry e badges Manual/Baseada em evidência, criação de evidência, lista com status/papéis/“Manual prevalece”/confiança qualitativa, revisão ADMIN (Aprovar/Rejeitar); estados loading/empty/erro/saving/validação; sem JSON cru, sem decimais, sem IDs internos; Chat/seletores intactos.

## 11. Ownership

Originais por `character.userId`; materializados por `character.universeId`; terceiros/outro Universe = 404 leak-safe; catálogo global read-only (GET vazio; mutações 403; nunca cria Persona); review ADMIN global (D-057).

## 12. Universe Isolation

Persona A ≠ Persona B para o mesmo piloto factual em universos distintos; geração nunca cruza personas; API/UI leak-safe; testado em service, evidence workflow, geração e E2E.
