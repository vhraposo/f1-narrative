# V3.24.4 — Universal Driver Lore (Evidence curada para todo o grid)

## Problema

Somente Lando Norris, Max Verstappen e Pierre Gasly tinham Evidence biográfico rico em
`data/external/biography/curated-evidence.json`. Os demais pilotos recebiam apenas a biografia
factual compacta derivada do espelho/F1DB (nascimento, nacionalidade, estreia, equipes,
estatísticas), sem origem, kart e categorias de base.

O mecanismo (pipeline, coverage, planner, composer, validator, fallback) já estava correto — faltava
matéria-prima. V3.24.4 preenche o catálogo pela mesma fórmula, sem exceções por piloto.

## Fórmula (a mesma para todos)

CURRENT GRID (descoberto via `WorldState.currentSeasonId` + `SeasonDriverEntry`)
→ evidence curada (`curated-evidence.json`, keyed by F1DB driver id)
→ normalização/claims
→ coverage (`evaluateBiographyCoverage`, rich = ≥5 áreas relevantes)
→ planner/composer/fallback (`RICH_DETERMINISTIC` sem LLM)
→ quality validator
→ persistência versionada
→ Public Profile determinístico
→ Personality evidence.

## Pesquisa real (fontes)

Pesquisa por piloto conduzida sobre fontes primárias, com URLs verificadas e registradas:
Formula 1 (páginas oficiais de piloto e Hall of Fame), sites oficiais das equipes (Mercedes, Ferrari,
McLaren, Red Bull, Racing Bulls, Alpine, Haas, Audi/Sauber, Williams, Aston Martin, Cadillac),
sites oficiais dos pilotos e Honda Global; imprensa confiável apenas quando o fato não existia em
fonte oficial (ex.: detalhes de kart de Hamilton/Lawson/Bottas/Stroll). Nenhuma prosa foi copiada:
cada fato virou claim estruturado (`category`, `key`, `value`, `display` pt-BR, `year/endYear`,
`authority`, `sourceRef`, `attribution` quando aplicável).

Categorias cobertas: IDENTITY, ORIGIN, KARTING, JUNIOR_CAREER, F1_ENTRY, TEAM_HISTORY,
F1_ACHIEVEMENTS, PUBLIC_PERSONALITY, INTERESTS, PROJECTS, CURRENT_CONTEXT.

## Dataset final

- 23 drivers do grid DEV (22 do fixture de QA + Yuki Tsunoda, presente no roster real do DEV).
- 103 fontes; 16 a 34 claims curados por piloto (média ~22).
- `generatorVersion` atualizado para `curated-evidence.v2` (muda o hash → `evidenceVersion` nova →
  bios antigas viram STALE e são regeneradas).
- Mínimo garantido por piloto: ORIGIN 3+, KARTING 3+, JUNIOR_CAREER 4+, F1_ENTRY 1+; PERSONALITY/
  INTERESTS/PROJECTS só quando documentados (sem invenção).

## Aliases data-driven

`aliases` no JSON resolve diferenças de nome entre espelho e F1DB de forma genérica:
`{"carlos-sainz": "carlos-sainz-jr"}`. Além disso, `resolveF1dbDriverStrict` passou a ignorar
sufixos geracionais (Jr./Sr./II/III) na comparação exata — melhoria genérica de resolução, não
exceção por piloto.

## Bios determinísticas versionadas

O fallback rico/compacto agora registra um `ExternalKnowledgeSource` próprio
(`CURATED`/`BIOGRAPHY_PAGE`, título "Biografia determinística (biography-composer.v3)") com
metadata `{ generatorVersion, evidenceVersion, fingerprint, mode, evidenceSources }`, deduplicado por
fingerprint. Consequências:

- `readBiographyState` detecta STALE por `evidenceVersion`/`generatorVersion` para bios determinísticas
  (antes só as geradas por LLM eram detectadas) — qualquer mudança real de curadoria dispara
  regeneração em background, sem bloquear o GET.
- Backfill idempotente: com evidência atual, 46/46 `skipped`, 0 falhas.
- Perfis compartilhados entre universes: o segundo character classifica o run pelo `mode` persistido
  (`RICH_DETERMINISTIC`) em vez de NOT_REQUESTED.

## Resultado DEV
