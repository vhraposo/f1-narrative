# V3.15 — Linha do Tempo Histórica: Questões Abertas (congeladas na V3.15)

> Todas as 8 questões foram resolvidas com os defaults congelados antes da implementação.
> Não há questão aberta bloqueante; os itens abaixo registram o comportamento implementado.

## OQ-1 — Troca de piloto/equipe em resultado — **RESOLVIDA (UNSUPPORTED v1)**
- **Default implementado:** correção de `RaceResult` aceita apenas `position`/`status`/`grid`; não há campos de piloto/equipe no payload (`.strict()` rejeita). Troca de piloto/equipe da linha histórica permanece fora do v1.
- **Revisão futura:** exigiria kind próprio com regras de unicidade/entries/narrativa.

## OQ-2 — Auto-cascade do `#1` — **RESOLVIDA (NÃO)**
- **Default implementado:** preview mostra `championBefore/championAfter` e `numberImpact { currentHolderId, expectedChampionId, requiresAction }`; apply não reescreve `SeasonDriverEntry.number`/`DriverProfile.number`; reatribuição é ação explícita via `setDriverNumber` (regra do campeão derivado + unicidade + `NUMBER_CORRECTED`); override manual prevalece.

## OQ-3 — Regeneração automática de narrativa — **RESOLVIDA (NÃO)**
- **Default implementado:** correções não apagam/editam/regeneram Event/News/Memory/Relationship; preview sinaliza `narrativeStaleEventIds` (Event com `payload.raceId` afetado) para revisão humana.

## OQ-4 — Evolution — **RESOLVIDA (bloqueio conservador)**
- **Default implementado:** correção que afeta temporada com `ATTRIBUTE_EVOLVED` aplicado é bloqueada com `409 EVOLUTION_STALE` (preview e apply); nenhuma evolução é rerodada; fingerprint segue como auditoria/idempotência.

## OQ-5 — Standings importados — **RESOLVIDA**
- **Default implementado:** `STANDING_CORRECTED`/CRUD de standing só é permitido quando a temporada **não possui RaceResult** (senão `409 DERIVED_STANDING`); com resultados, corrige-se a causa (resultado) pela Timeline.

## OQ-6 — Agenda — **RESOLVIDA (restrita)**
- **Default implementado:** correção de calendário via `RACE_UPDATED` (nome/data/round/status/sprintOverride) com bloqueio `SCHEDULE_ORDER_UNSAFE` quando a mudança reordenaria corridas finalizadas; CRUD de corrida `FINISHED` pela API pública retorna `USE_TIMELINE_CORRECTION`.

## OQ-7 — Snapshot completo — **RESOLVIDA (NÃO)**
- **Default implementado:** `WorldSnapshot` continua com `world + standings`; correções usam valores absolutos + checkpoint pré-correção; nenhum snapshot integral de resultados/entries/atributos.

## OQ-8 — ADMIN — **RESOLVIDA (dono-only)**
- **Default implementado:** leitura/escrita da Timeline seguem ownership do Universe (`ensureUniverse`); ADMIN não ganha permissão de editar universos de terceiros; nenhum privilégio novo criado.
