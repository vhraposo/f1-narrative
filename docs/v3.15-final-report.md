# V3.15 — Historical Timeline / Alternate History: Relatório Final

> Branch `V3-NewFeats` · commits V3.15.1–V3.15.8 (locais; sem push/merge/main).

## 1. Objetivo

Permitir visualizar a história do próprio Universe, comparar com o External Mirror, corrigir acontecimentos históricos suportados com preview determinístico e aplicar de forma atômica, recomputando derivados sem criar segundo sistema temporal.

## 2. Arquitetura

Correction Command + TimelineEvent append-only + WorldSnapshot + recompute determinístico. Uma única timeline canônica por Universe; sem branches, sem void, sem full event sourcing, sem banco espelho. Lock `timeline:<universeId>` em todas as operações sensíveis.

## 3. Source of truth

FONTE: `RaceResult.position/status/grid`, `RaceSessionResult` SPRINT (posição/status/elegibilidade), `Race` calendário, `SeasonDriverEntry.number`. DERIVADO: `points`, `ChampionshipStanding`, campeão (sem entidade), `DriverProfile.number` (cache). HISTÓRICO: TimelineEvent/WorldSnapshot. NARRATIVO: Event/News/Memory/Relationship. EXTERNO: `External*` (nunca sobrescrito).

## 4. Timeline

`TimelineEvent` append-only com `sequence` única por universe, `worldDate`, `causedBy`, `supersedesId` (SetNull). 9 kinds, incluindo `RACE_SESSION_RESULT_CORRECTED`. Replay: snapshot mais recente (`world+standings`) → reaplica tail ordenado por `(worldDate, sequence)` pulando superseded.

## 5. Correction command

5 kinds tipados: `RACE_RESULT_CORRECTED` (position/status/grid), `RACE_SESSION_RESULT_CORRECTED` (position/status/elegibilidade), `NUMBER_CORRECTED`, `STANDING_CORRECTED` (só sem resultados), `RACE_UPDATED` (com proteção de ordem). Validação semântica antes de qualquer escrita; supersession exige mesmo kind; valores absolutos; nenhum void.

## 6. Preview

Executa o mesmo motor em `$transaction` que sempre aborta (rollback garantido) e retorna diff (RESULT/SPRINT/CALENDAR/NUMBER/STANDING/CHAMPION), campeão antes/depois, `narrativeStaleEventIds`, `numberImpact` e `previewToken = sha256(universe, lastSequence, world, standings, comando)`. Nenhuma entidade é persistida.

## 7. Apply

Lock de timeline → revalida token do estado atual (409 `PREVIEW_STALE`) → validação → checkpoint pré-correção → append corretivo → recompute → invariante de persistência → commit atômico. Falha = rollback total.

## 8. Recompute

Reutiliza `recomputeSeasonStandings` e o replay existente; nenhum engine duplicado. Determinístico: mesmos eventos/estado ⇒ mesmo resultado (testado 2×).

## 9. Race correction

`position/status/grid`; `points` rejeitado (`DERIVED_FIELD`) e sempre derivado da tabela por posição; posições repetidas toleradas (dead heat existente); corrida finalizada bloqueia CRUD público (`USE_TIMELINE_CORRECTION`).

## 10. Sprint correction

`RaceSessionResult` SPRINT: posição/status/elegibilidade (merge em `metadata.eligibility`); pontos derivados da tabela 8..1 e elegibilidade (≥50% e sem neutralização); recompute de standings.

## 11. Champion

Derivado de `ChampionshipStanding.position===1`; nunca editável. Preview expõe before/after; apply não congela campeão nem cria entidade.

## 12. Numbers

`SeasonDriverEntry.number` é fonte; `DriverProfile.number` cache. `setDriverNumber` com lock/uniqueness/#17/#1/champion-derivation/`NUMBER_CORRECTED`. Correção histórica **não** cascateia `#1`; reatribuição é ação explícita e override manual prevalece.

## 13. Divergence

`GET /api/timeline/divergence?seasonId=` compara Universe × External via bindings (races/results/standings) com classificações MATCH/DIVERGENT/UNIVERSE_ONLY/EXTERNAL_ONLY (NO_EXTERNAL reservado). Leitura pura; refresh nunca sobrescreve o Universe.

## 14. Hardening

Writers classificados: lifecycle (simulação/weekend/finalize/world progression/número) preservado com lock; mutável público endurecido (resultados/corridas FINISHED → `USE_TIMELINE_CORRECTION`; standings derivados → `DERIVED_STANDING`). Finalize ganhou ownership leak-safe e lock.

## 15. API

`GET /api/timeline` (filtros season/from/to/driver/team/race/kind/correctionsOnly, cursor, limit), `GET /api/timeline/events/:eventId` (cadeia de supersessão), `GET /api/timeline/divergence`, `POST /api/timeline/corrections/preview`, `POST /api/timeline/corrections/apply`, mais rotas legadas (`/advance`, `/corrections`, `/recompute`, `/snapshots`). Schemas Zod `.strict()`; erros 400/401/404/409 sanitizados.

## 16. UI

Narrativa → Linha do Tempo: filtros (temporada/corrida/piloto/equipe/tipo/datas/somente correções), lista cronológica com badges (correção/efetivo/substituído), detalhe com valores e cadeia de supersessão, painel de divergência externa. Loading/empty/error/retry; dark/light via design system. Preview/apply via API (editor visual completo fica como future work).

## 17. Concurrency

Lock por Universe serializa corrections/advance/finalize/número/world; preview sem lock pode ficar stale (rejeitado no apply); applies concorrentes com o mesmo token → exatamente um vence; correção + world patch concorrentes não corrompem.

## 18. Security

Dono-only por Universe; 401 sem sessão; 404 leak-safe para terceiros; campos derivados rejeitados; malformed payload 400; stale 409; sem stack/SQL/Prisma nos corpos de erro.

## 26. Limitations

Troca de piloto/equipe e criação retroativa de resultado ausente: UNSUPPORTED v1. Sem void/rollback de correção (corrigir de novo é o caminho). Sem regeneração narrativa nem rerun de evolução (staleness sinalizada/bloqueada). Sem snapshot completo de resultados/entries/atributos. UI de preview/apply é via API (editor visual minimal fica para future work). `points` continua aceito no CRUD de corrida aberta (pré-finalização), como antes.

## 27. Future work

## 28. Manual validation guide

1. Abrir Narrativa → Linha do Tempo; aplicar filtros e abrir detalhes de eventos/correções. 2. Verificar divergência externa em uma temporada materializada. 3. Via API, gerar preview de correção de resultado e conferir diff/campeão/impacto sem alterações no banco. 4. Aplicar com o token; conferir standings/champion e a cadeia de supersessão. 5. Tentar editar o mesmo resultado pela rota legada → 409. 6. Reatribuir `#1` explicitamente quando o campeão derivado mudar. 7. Confirmar external refresh sem sobrescrever o Universe.
