# V4.2 — Dynamic Conversations

## Objetivo

Permitir turnos autônomos (AI↔AI e multi-party) sobre a infraestrutura existente de
Conversation/Message, com seleção de speaker determinística, turn budget, anti-loop e LLM restrito à
linguagem — sem duplicar o pipeline de turnos iniciados pelo usuário.

## Estado anterior (auditoria)

- `Conversation` sem status/universe/turnos; ownership derivado por participante.
- `executeTurn` (user-initiated) já possui seleção determinística (`response-orchestrator`) e
  persistência canônica; `assembleGenerationBundle` monta contexto com limites fixos; providers:
  `nullProvider` e `OllamaProvider` (sem retry/structured outputs).
- Behavior V4.1: Command Layer com stale/idempotência/lock; `executeMessageCommand` usava texto
  determinístico e não aceitava conteúdo injetado.
- Nenhuma sumarização de conversa existia.

## Arquitetura implementada

```
POST /api/conversations/:id/autonomous-turn
  ownership (participant.character.userId)
  → planConversationTurn (status, budgets, inatividade, elegibilidade, speaker determinístico)
  → summarizeConversation (extrativo, reconstruível)
  → evaluateBehaviorDecision(CONVERSATION_TURN_DUE)   [Goals + Policy + Score + AiDecision]
  → assembleGenerationBundle (provider opcional; fallback determinístico)
  → executeBehaviorDecision(contentOverride)          [Command = único writer; stale/fingerprint/lock]
  → Message persistida + AiDecision EXECUTED
```

- `GET /api/conversations/:id/turn-plan` — leitura pura do plano (observabilidade/testes).
- `POST /api/conversations/:id/autonomous-turn` — executa no máximo UM turno por chamada.

## Turn Engine (`conversation.turn-engine.ts`)

- `planConversationTurn` (puro) com reasonCodes: READY, CONVERSATION_NOT_FOUND/NOT_ACTIVE,
  NO_AI_PARTICIPANT, NO_MESSAGES, CONVERSATION_INACTIVE, TURN_BUDGET_EXHAUSTED,
  CONVERSATION_BUDGET_EXHAUSTED, SAME_SPEAKER_LIMIT, NO_ELIGIBLE_SPEAKER.
- Speaker determinístico: menção direta no último texto → `DIRECT_MENTION`; caso contrário próximo
  participante (excluindo o último speaker) → `NEXT_PARTICIPANT`; senão o mesmo speaker se dentro do
  limite → `DETERMINISTIC_ORDER`; ordem final por `characterId`.
- USER characters nunca são selecionados (apenas AI); indisponibilidade exclui candidatos.
- `summarizeConversation`: extrativo, limitado por `maxSummaryChars`, determinístico e reconstruível
  (não persistido; histórico canônico intacto).

## Limites configuráveis (`conversation.policy.ts`)

`CONVERSATION_MAX_AI_TURNS_PER_ROUND` (4), `CONVERSATION_MAX_AI_MESSAGES` (20),
`CONVERSATION_MAX_CONSECUTIVE_SPEAKER` (2), `CONVERSATION_INACTIVITY_TIMEOUT_MS` (72h),
`CONVERSATION_MAX_SUMMARY_CHARS` (600), `CONVERSATION_RECENT_MESSAGE_WINDOW` (12).

## Schema

Migration aditiva `20261001200000_add_conversation_status`: enum `ConversationStatus`
(ACTIVE/PAUSED/COMPLETED/CANCELLED) + `Conversation.status` default ACTIVE + índice. Nenhum campo de
budget no banco (configurável por env).

## Behavior/Command

- Trigger novo `CONVERSATION_TURN_DUE` → candidato RESPOND (`POLICY_CONTINUE_CONVERSATION_TURN`).
- `executeBehaviorDecision(decisionId, { contentOverride })`: texto validado (1–5000), gravado via
  `SendMessageCommand` com `contextJson.language {provider, model, fallback}`; `AiDecision` registra
  command/fingerprint/latência/language. `AVAILABILITY_OPEN` passa a tratar ausência de registro como
  disponível (alinhado ao Turn Engine).
- Anti-loop: budget + fingerprint + repeated-content (texto igual à última mensagem → não envia).

## Providers

Provider continua injetado (Ollama quando `OLLAMA_MODEL` definido; `nullProvider` por padrão).
Falha do provider → fallback determinístico, turno persiste com `fallback: true`; conversa não quebra.
Nenhum provider é obrigatório.

## Invariantes

- Message é o único registro canônico; LLM nunca escreve estado.
- Command revalida participação/controller/universo e é o único writer da mensagem.
- USER nunca age autonomamente; ownership 404; status não-ACTIVE bloqueia; um turno por chamada.
- Nenhuma Memory/Relationship/Event criada nesta fase (V4.3/V4.4).
- Determinismo: sem `Math.random`; seleção por regras; `worldDate` explícito no plano.

## Testes

- `conversation.turn-engine.test.ts` (11, puros): menção, alternância, budgets, consecutivo,
  inatividade, status, sem IA, indisponível, sumário, limites configuráveis.
- `conversation.autonomous.test.ts` (9, integração): execução com provider + audit, alternância de
  speaker, plano read-only, fallback em falha, conteúdo repetido, pausa, ownership 404, sem IA,
  budget por env.

## Limitações

- Um turno por chamada (orquestração contínua é V4.7); sem streaming no turno autônomo.
- Sumário extrativo sem LLM (condensação rica pode vir depois, permanecendo derivada).
- Turn budget por rodada/total; sem agendamento temporal por personagem (V4.7).
- Provider OpenAI/structured outputs não adicionados (não necessários nesta fase).
