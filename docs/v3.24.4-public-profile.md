# V3.24.4 — Public Profile derivado de Evidence

## Causa raiz do "Nenhuma informação pública confiável encontrada."

Auditoria no código:

- UI: `PublicPersonaPanel` (apps/web/src/components/pilot-knowledge/pilot-knowledge-panels.tsx)
  mostrava a mensagem quando `pilot.persona.available === false`.
- API: `pilot.persona` vinha de `getExternalPersonaView` (pilot-knowledge.persona.ts), que lê
  `ExternalDriverProfile.persona` (`ExternalDriverPersona`).
- DEV: `ExternalDriverPersona` = **0 linhas** → `reason: "NO_PERSONA"` → mensagem de vazio para
  todos, inclusive Max/Lando/Gasly, apesar da evidence curada aprovada.

Ou seja: o Perfil público dependia exclusivamente de uma entidade que nenhum provider preenche,
ignorando os claims aprovados (F1/equipe/piloto/F1DB) que já existiam.

## Novo read model

`pilot-knowledge.public-profile.ts` → `getPublicProfileView(characterId)`:

- Reutiliza `loadBiographyEvidenceForCharacter` (mesmo claim set da biografia: espelho + F1DB +
  curadoria) — nenhum LLM, nenhum fetch de rede no GET.
- Status:
  - `EMPTY`: nenhum claim aprovado.
  - `PARTIAL`: há claims, mas cobertura limitada (menos de 3 áreas curadas relevantes e sem rich).
  - `AVAILABLE`: coverage rich (≥5 áreas relevantes) ou ≥3 áreas curadas relevantes.
- `summary`: composição determinística em pt-BR a partir dos claims (identidade → base → F1 →
  conquistas → contexto atual), limite de 900 caracteres.
- `facts`: claims curados selecionados por categoria (Origem, Kart, Categorias de base, Chegada à
  F1, Equipes, Conquistas, Personalidade pública, Interesses, Projetos, Temporada atual) com fonte.
- `sources`: fontes únicas com provider/título/URL (F1, equipe, piloto, FIA, imprensa confiável).
- Exposto em `GET /api/pilot-knowledge/drivers/:characterId` como `pilot.publicProfile`.

A UI ganhou o card "Perfil público" (status, resumo, informações verificadas e fontes) e a seção
"Traços públicos observados" (ExternalDriverPersona, quando existir). Somente `EMPTY` mostra
"Nenhuma informação pública confiável encontrada.".

## Performance

`getPublicProfileView` roda no GET em ~54 ms no DEV, lendo claims já montados a partir de dados
persistidos/arquivo local. Nenhuma geração, provider externo ou LLM é chamado na abertura.

## Testes

- API `pilot-knowledge.public-profile.test.ts` (4): AVAILABLE com summary/facts/sources reais;
  PARTIAL com claims derivados; EMPTY sem binding; summary sem JSON/markdown.
- Web `pilot-knowledge-panels.integration.test.tsx` 14–16: AVAILABLE/PARTIAL/EMPTY na UI.

## Decisão

- D-102 — Public Profile é read model derivado de claims aprovados; `ExternalDriverPersona` é
  complemento, nunca a única fonte.
